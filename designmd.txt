
# FIGMA AGENT MASTER PROMPT
# PELITA — Adaptive Learning Platform

You are a Senior Product Designer, UX Architect, and UI Design Specialist.

Your task is to design a complete, high-fidelity, responsive web application for PELITA, an adaptive learning platform for children whose education has been interrupted by health-related circumstances.

You must follow the provided `design.md` as the primary source of truth.

You must also use the uploaded Pijar mascot reference image as the official character asset.

Do not replace the mascot with a newly generated character.

Do not ignore the product requirements.

The final result must be a complete, organized, interactive Figma design system and prototype.

---

# 1. PROJECT OBJECTIVE

Design PELITA as a modern educational web application with three distinct role-based experiences:

1. PELITA Anak.
2. PELITA Pendamping.
3. PELITA Admin.

The platform must be:

- Desktop-first.
- Fully responsive.
- Mobile-friendly.
- Tablet-compatible.
- Accessible.
- Consistent.
- Interactive.
- Ready to be translated into a frontend implementation.

This is a RESPONSIVE WEB APPLICATION.

Do not design it as three independent native mobile applications.

Use a shared design system with role-specific navigation and experiences.

# 6. OFFICIAL MASCOT — PIJAR

THIS SECTION IS CRITICAL.

Use the uploaded original Pijar image as the official mascot.

The reference image contains a 4-column × 3-row expression sheet.

The character is a cute orange-yellow flame mascot with:
- Orange-red flame hair.
- Yellow glowing body.
- Large brown eyes.
- Red-orange cape/scarf.
- Golden diamond chest accessory.
- Rounded cartoon proportions.

Do not redesign the mascot.

Do not create a different mascot.

Do not change its facial identity.

Do not change its costume.

Do not change its defining colors.

Do not remove its golden chest accessory.

## 6.1 Asset Preparation

Separate the original 12 poses into individual image assets.

Preserve the original illustration.

Crop each pose carefully.

Do not crop:
- Flame details.
- Hands.
- Feet.
- Cape.
- Golden accessory.
- Facial expressions.

Remove white backgrounds only when technically possible without damaging the character.

Use transparent PNG assets when available.

If clean extraction is not possible, preserve the original reference sheet and request separate assets instead of recreating the mascot.

## 6.2 Create Mascot Component

Component name:

Mascot/Pijar

Create variants:

- Welcome.
- Happy.
- Calm.
- Curious.
- Excited.
- Surprised.
- Empathetic.
- Determined.
- Resting.
- Peek.
- Caring.
- Transition.

## 6.3 Expression Mapping

Use the expressions according to the situations below.

| Expression | Usage |
|---|---|
| Welcome | Greeting and home |
| Happy | Successful learning |
| Calm | Learning instructions |
| Curious | Hints and exploration |
| Excited | Positive reinforcement |
| Surprised | Interesting discoveries |
| Empathetic | Emotional support |
| Determined | Non-punitive motivational context |
| Resting | Rest mode |
| Peek | Tooltips and contextual guidance |
| Caring | Teman Cerita |
| Transition | Decorative transitions |

The angry-looking expression must never be used when a child gives an incorrect answer or reports negative emotions.

It may be omitted from child-facing screens.

## 6.4 Mascot Interaction

Pijar should appear contextually.

Examples:

Home:
Pijar welcomes the child.

Check-in:
Pijar responds gently to the child's selected condition.

Learning map:
Pijar guides the child through the journey.

Correct answer:
Pijar celebrates.

Incorrect answer:
Pijar encourages another attempt.

AI Tutor:
Pijar accompanies the explanation.

Rest:
Pijar uses the sleeping expression.

Teman Cerita:
Pijar uses the caring expression.

Session completed:
Pijar celebrates.

Guardian:
Pijar appears sparingly.

Admin:
Pijar appears only as a brand accent.

## 6.5 Mascot Motion

Use subtle motion prototypes.

Idle:
Gentle floating.

Happy:
Small bounce.

Curious:
Gentle tilt.

Rest:
Slow downward movement.

Empathetic:
Subtle breathing-like movement.

Avoid distracting or aggressive animation.

# 9. VISUAL DESIGN REQUIREMENTS

## 9.1 Child Interface

The child interface is the most important visual experience.

Use:
- Light warm cream background.
- Brick (#BF4338) for main actions; gold and orange as accents.
- Sand surfaces for cards and answer buttons; soft pink for decoration.
- Rounded cards.
- Large buttons.
- Friendly illustrations.
- Learning journey paths.
- Pijar as the main character guide.

The learning map should be a central visual identity.

Use a Duolingo-inspired learning path with:
- Connected learning nodes.
- Clear progress states.
- Current learning position.
- Friendly milestones.
- Grade-based organization.

Do not use:
- Leaderboards.
- Competitive rankings.
- Punitive streaks.
- Countdown timers.
- Public performance comparisons.
- Red incorrect-answer screens.

## 9.2 Guardian Interface

Use a more structured layout.

Prioritize:
- Information hierarchy.
- Clear data visualization.
- Readable charts.
- Progress status.
- Attention alerts.
- Pending decisions.
- Report generation.

Use professional typography.

Keep the interface warm and approachable.

Avoid excessive cartoon illustrations.

## 9.3 Admin Interface

Use a modern SaaS dashboard.

Prioritize:
- Sidebar navigation.
- Data tables.
- Filters.
- Parameter configuration.
- Status badges.
- Review queues.
- Evaluation metrics.
- Audit logs.

The admin dashboard should look professional and operational.
